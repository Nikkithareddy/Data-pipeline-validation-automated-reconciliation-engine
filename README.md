# Data Pipeline Validation & Automated Reconciliation Engine

Validates data after an ETL load by comparing a **source extract** with the **target table**, using scripted SQL checks.
Built with **SQL, Python, MS Excel and Git**.

## What it checks
| Category | Checks |
|---|---|
| Completeness | row counts, source records missing from target, unexpected target records |
| Nulls | required columns (`customer_id`, `amount`, `order_date`) |
| Duplicates | repeated business keys |
| Data types | non-numeric amounts, wrong date format |
| Validity | values outside allowed domain, non-positive amounts |
| Reconciliation | total amount, row-level mismatches via JOIN on key, per-customer totals, per-status counts |

Every check is a plain `.sql` block in `sql/` that returns a violation count (expected 0). Failed checks also run a detail query
so the offending rows are captured.

## Outputs
`python run_validation.py` writes **`output/execution_tracker.xlsx`** (a sample is committed):
- **Execution Tracker**: every check with expected/actual/PASS-FAIL/timestamp, colour-coded
- **Summary**: pass rate per category, before vs. after cleanup
- **Error Details**: offending rows for each failed check (schema and data errors)

## Cleanup verification
`sql/cleanup.sql` repairs the target from the source (dedupe, remove extras, reload mismatched/missing rows), then the same checks
re-run to prove the fix: the sample run goes from **3/15 to 15/15 checks passing**.

## Run it
```bash
pip install -r requirements.txt
python run_validation.py        # before/after run + Excel tracker
pytest                          # engine tests
```

## About the data
Sample data is generated by `src/sample_data.py`: 100 orders, with known defects injected into the target (3 missing records,
1 extra, 2 duplicates, 2 null customer IDs, 1 null amount, 2 changed amounts, 1 text amount, 1 bad date, 1 bad status).
The tests assert the engine finds exactly those and produces no false positives on clean data. One test shows why counts alone
aren't enough: the missing, extra and duplicate rows cancel out, so the row-count check passes while the other checks fail.

SQL runs on SQLite so it works anywhere with no setup. Where MySQL syntax differs (regex type checks) the equivalent is in a comment.
To use another database, change the connection in `run_validation.py`.

## Structure
```
sql/       validation_checks.sql, reconciliation_checks.sql, cleanup.sql
src/       sample_data.py, engine.py (runs checks), tracker.py (Excel report)
tests/     test_engine.py
output/    execution_tracker.xlsx (sample run)
```
